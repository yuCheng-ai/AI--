# 实施分工与验收计划

目标是完成可持续制作短剧的最小闭环：从一集剧本得到镜头和人物资产，生成并选择候选，完成配音字幕与时间轴，输出可播放视频。先用于内部团队，再根据真实用量扩展 SaaS。

## 当前实施状态

截至 2026-10-11，可运行的第一版后端已交付，实际启动与接口记录见 [运行说明](running.md)。本计划包含后续目标，不代表 P0 的所有条目已经完成。

- 已实现：12 个 Maven 模块的依赖骨架，API 和迁移进程、Docker 启动、数据库迁移、Session/CSRF、工作空间权限、项目及镜头修订、本地媒体存储、Swagger、请求和 SQL 诊断日志。
- 尚需补齐的工程基础：用户和成员管理入口、登录保护、持久化操作审计、构建时的模块边界约束、备份与恢复流程。
- 后续业务阶段：任务调度和 Worker、模型供应商、费用账本、云存储适配、前端与成片制作。目前 jobs/models/assets/usage/generation/editing/workbench 仅保留模块及依赖边界。
- 验证方式：采用构建、实际启动、真实接口请求和手动故障检查；不编写测试用例。下文原先的自动化测试设想不属于当前执行范围。

## 开工顺序与验收边界

采用“后端最小底座先行、前端按契约并行、单镜头闭环优先”的实施顺序。模块和数据所有权已有设计基线；依赖兼容、供应商行为与媒体效果仍需运行验证。

| 顺序 | 后端交付 | 前端同步交付 | 通过条件 |
|---|---|---|---|
| P0-A：可运行底座 | 构建与 Compose、迁移、工作空间会话、权限、日志、错误格式、存储接口 | 工作台路由、登录页与上传入口，使用版本化契约 | 从干净环境启动，登录后完成真实上传和受控预览 |
| P0-B：最小业务契约 | 项目/集/镜头修订的创建与读取，OpenAPI；明确任务状态和错误示例 | 镜头详情、草稿保存、任务反馈与候选区域，按 Stub 开发异步状态 | 两个工作空间互相隔离；版本冲突保留草稿；契约生成无漂移 |
| P1：单镜头闭环 | 幂等、预算、jobs、供应商 Stub，再接一个真实供应商 | 提交、刷新恢复、查看结果、人工选片 | 通过重复提交、宕机恢复、回调乱序和迟到结果验证 |
| P2–P3：制作流程 | 资产复用、结构化剧本、批次、音频字幕、固定时间轴渲染 | 分镜制作、资产管理、时间轴和导出 | 完成一集可播放成片并核对版本、时长与费用 |

Maven 模块目录按依赖清单建立，业务实现随纵向流程推进。P0 不要求填满所有模块、不实现全部云厂商适配器，也不以目录数量作为验收依据。架构师与 Java 共同负责底座的事务和故障恢复，前端在 DTO、错误结构和状态语义冻结后立即并行。

时间轴风险提前验证：P0 使用少量固定本地测试片段，核对整数帧裁剪、字幕位置与音频采样规则，并比较浏览器编辑预览和服务端样片。此验证只覆盖格式契约与已知素材，不提前扩展完整剪辑器。

## 开工前后需要落实的事项

| 事项 | 当前处理方向 | 完成时点与责任 |
|---|---|---|
| 权限与账号初始化 | 内部使用先采用管理员初始化和邀请加入；管理员、制作、审核、只读角色冻结成操作矩阵，权限在后端执行 | P0，架构师/Java；前端按同一动作权限显示界面 |
| 依赖与运行时兼容 | 固定 Java Toolchain、Boot/MP/驱动与构建插件版本，实际启动并验证 PostgreSQL | P0-A，Java |
| 首个对象存储实现 | 先选一个本地或云后端，验证签名、分片、Range、CORS 与持久挂载；保留统一接口 | P0-A，Java/前端 |
| 供应商能力与样片质量 | 核实参考素材、输出规格、查单、幂等、取消、费用和链接有效期；用连续镜头样片评估角色一致性，不以任务成功率代替成片质量 | P1，架构师/Java；前端提供比较与选片 |
| 容量和业务限制 | 明确文件大小、批次上限、并发、scratch 容量和预算风险阈值，成为配置与接口校验 | P0 给保守开发默认值，P1–P3 实测调整 |
| 运维处理入口 | 提供重新查单、重试归档、查看占用与费用等受权限控制的动作；未知提交不可通过通用重试直接再付费，修正必须留审计 | P1 最小处理能力，P4 完善工作台 |
| 交付与恢复 | 构建、模块检查、迁移和契约检查进入 CI；单一镜像版本发布三个角色，备份/恢复和旧任务升级验证 | P0 建门禁，P4 完成恢复演练 |

部署机器、存储容量和首个真实模型账号在使用对应资源前落实；这些不阻塞本地底座与 Stub 开发。不能据设计文档宣称供应商恢复、存储迁移或媒体同步已经验证成功。

## 角色和责任

| 角色 | 主责 | 必须交付 | 评审边界 |
|---|---|---|---|
| 架构师 | 模块依赖、数据所有权、事务、任务恢复、契约和部署 | 模块白名单、核心状态表、OpenAPI 约定、故障场景与发布规范；参与任务内核和预算并发实现 | 审查 Java 跨模块依赖、付费提交恢复及前后端版本语义 |
| 高级 Java | 业务 API、持久化、模型接入、任务与媒体流水线 | Maven 模块、Flyway、权限、预算账本、供应商适配器、Worker、FFmpeg 合成、可观测性 | 不替前端规定交互；通过契约定义能力与错误处理 |
| 资深前端 | 工作台、编辑状态、媒体交互、任务反馈、时间轴 | React 工作台、契约客户端、草稿和冲突恢复、上传、镜头候选、时间轴、浏览器验收 | 不在前端复制预算或供应商状态机；对导出契约共同验收 |

架构师承担可执行约束和高风险链路的实现评审，不只输出文档。Java 和前端并行开发时共用版本化接口及带故障状态的 Stub；每阶段都交付可操作的纵向流程。

## P0：工程骨架和契约

交付：

- Maven Wrapper、父 POM、12 个模块目录、boot 的 API/model-worker/media-worker 运行角色。
- 锁定 Java、Spring Boot 及第三方依赖完整版本；前端锁定 pnpm 与依赖，提交 lockfile。
- PostgreSQL、对象存储、开发反向代理的 Compose 环境；独立迁移账号和应用账号。
- 工作空间、基本成员权限、同源 Session 与 CSRF。
- Security 过滤链、执行上下文解析、Bean Validation、统一错误处理；供应商回调独立验签入口。检查自定义 Filter 注册一次、后台入口同样执行授权及幂等约束。
- 对照模块白名单审查无环依赖和跨模块 internal；集中错误格式与 OpenAPI 导出。当前采用构建、源码审查和运行核验，不增加测试用例。
- MyBatis-Plus Boot 4 Starter、模块内部 Mapper/XML、租户上下文与精确 SQL 绕过清单；SQL 诊断和敏感字段验证。
- SLF4J/Logback 结构化日志、请求与任务关联、异常边界、Hikari 指标、日志轮转和管理端口限制，按 [Java 工程规范](java-engineering.md) 验收。
- 前端路由、工作台框架、生成 API 客户端、任务状态和冲突场景的模拟数据。

验收：各角色可启动；空数据库可迁移；两个工作空间的资源访问互相隔离；前端可登录读取本工作空间。审查实际 POM、源码 import 与模块白名单一致，普通 Mapper 与精确 SQL 均完成跨租户核验，日志能关联请求且不泄漏敏感值。Worker、前端及供应商回调属于后续交付，不代表当前底座已经提供。

## P1：一个镜头的可靠闭环

交付：

- 建立一个项目、一集、一个镜头修订和一份参考媒体。
- 实现固定 jobs 调度及事务事件投递，具备租约恢复、明确重试策略和失败查询。
- generation 接入供应商 Stub，覆盖接单成功、超时后实际成功、重复回调、生成失败及费用延迟确认。
- usage 实现原子预占和幂等结算；workbench 建立目标绑定；content 附加并人工选择候选。
- 前端可提交、刷新恢复、看到真实阶段、比较候选与输入版本。
- 再接入一个经过能力核验的真实视频供应商，完成受控成本的样片验证。

验收：同一个用户意图只产生一个本地请求；安全恢复取决于供应商幂等与查单能力，不能用 Stub 成功替代真实验证。若供应商不支持恢复，超时后停在可核对状态且不自动再次付费。API 进程重启后仍能查到生成结果与费用。

P1 是开工优先级最高的风险验证。没有通过重复付费、宕机恢复和旧版本保护验收前，不扩大模型数量和批量生成规模。

## P2：完整制作素材链

交付：

- 剧本结构化草案及人工采纳、场次与镜头编辑。
- 工作空间角色、场景、道具及声音资产；项目绑定资产，镜头引用固定版本。
- 文本、图像、视频、语音各一个供应商适配器与明确能力表。
- 有限批量镜头生成、预算确认、子请求独立状态、批次取消。
- 上传分片恢复、素材归档、ffprobe、代理文件、缩略图及必要的波形。
- 资产变化后的复核提示、修订历史、镜头候选和选片。

验收：角色和场景能跨集复用；修改资产不会静默改变在途生成；旧任务完成后不覆盖新镜头；上传完成后未校验素材不可用于生成或导出。完成一集所需的固定版本素材准备。

## P3：时间轴、审片和导出

交付：

- 30 fps、单顺序视频轨、裁剪排序和硬切。
- 旁白/BGM/字幕，固定字体及样式，明确音频与帧转换规则。
- 前端草稿、撤销重做、冲突处理与服务器时间轴修订。
- 冻结渲染清单；媒体 Worker 输出低清审片与正式成片。
- 素材引用保留、临时目录清理、资源限制、进程取消和失败恢复。

验收：完成一集 60–90 秒视频，从剧本到输出走通；文件可播放，时长、片段边界、字幕与旁白位置符合已冻结的时间轴。使用带已知闪帧和音频脉冲的素材核对裁剪与同步，不仅依赖人工“看起来正常”。

## P4：内部试运行与 SaaS 基础

交付：

- 权限回收、跨租户隔离、供应商凭证管理、预算与实际用量核对。
- API 延迟、排队时间、供应商未知提交、待结算额度、失败原因、事件积压、媒体临时磁盘监控。
- 日志关联 workspaceId、operationId、providerSubmissionId、jobId 和 traceId；敏感凭证脱敏。
- 接入 Prometheus/Grafana 与集中日志检索，验证 Nginx 下 SSE 心跳、重连和缓冲配置。
- 数据库与对象存储备份、恢复演练、兼容升级、回滚与旧任务恢复说明。
- 根据实测并发固定工作空间、供应商账号及 FFmpeg 并发上限，保留容量余量。

验收：内部真实项目持续使用；核对账本与供应商用量；记录实测吞吐、成本和恢复耗时。SaaS 的套餐、订阅、支付和公开注册在商业化阶段单独实施，已有工作空间边界继续复用。

## 必须验证的故障矩阵

| 场景 | 必须保持的结果 | 主要责任 |
|---|---|---|
| 同一 Idempotency-Key 并发提交及响应丢失 | 一个操作、一份预占；不同 payload 冲突 | Java、架构师 |
| 接纳事务中任意一步异常 | 请求、绑定、预算、媒体引用和首任务一并回滚 | Java |
| 并发请求争抢剩余额度 | 原子预算规则成立，实际费用照实入账 | Java、架构师 |
| 提交意图落库后、HTTP 前或响应落库前杀 Worker | 安全查单或明确未知，不能盲重发 | Java、架构师 |
| 旧 Worker 在租约被接管后返回 | 不能改写当前业务状态；外部收据可核对 | Java |
| 回调早于提交响应、重复及乱序回调 | 同一个状态归并入口，终态不倒退，费用不重复 | Java |
| 供应商成功后文件下载失败 | 只重试归档，保留实际费用 | Java |
| 候选投递时杀进程 | 收据、候选、活动和 job 状态原子提交，重投不重复 | Java |
| 任务提交后用户改稿、归档目标或取消 | 旧结果保留可追溯，不能覆盖新内容或自动付费续跑 | 三角色 |
| 两个浏览器同时编辑 | 409 可理解，本地草稿仍在 | 前端、Java |
| SSE 重复、断线和游标过期 | 查询恢复正确状态，脏草稿不被覆盖 | 前端、Java |
| 工作空间成员权限被撤销 | 新请求拒绝，长期连接停止暴露活动 | Java、前端 |
| 用户伪造其他工作空间 ID 或媒体引用 | 服务端拒绝，不签名或下载其他租户对象 | Java |
| 分片上传中断、签名到期 | 恢复必要分片，后端独立核实完整对象 | 前端、Java |
| 渲染期间编辑时间轴或触发素材清理 | 导出使用原修订，仍被引用文件不被回收 | Java、前端 |
| 使用旧 payload 的任务跨版本恢复 | 兼容读取或明确待处理，不能误判成功 | Java、架构师 |

## 首版范围和实施纪律

第一阶段使用固定制作步骤，每类能力先接一个供应商。节点画布、开放工作流编排、多人实时协同、复杂转场、自动连续重生成和自建模型训练留到有生产证据后评估。

每阶段完成相应故障验证后再拓展功能。普通组件和纯展示代码不堆砌测试；测试集中于预算、恢复、版本冲突、租户隔离和媒体输出。精确工期应在 P1 真实供应商验证及时间轴交互样例完成后估计。

当前状态：可运行后端与依赖解析已经完成，Docker API 和数据库运行正常；供应商付费调用、任务故障恢复、完整媒体渲染及生产部署尚未验证。
